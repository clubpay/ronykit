# ee Postgres store

This module implements the [`ee`](../../../../ee) store contract with Postgres, pgx, and sqlc.

```go
pg, err := postgres.New(
	postgres.WithPrimaryDSN(primaryDSN),
	postgres.WithReplicaDSNs(replica1, replica2),
	postgres.WithMigration("001-order-indexes", func(ctx context.Context, tx pgx.Tx) error {
		_, err := tx.Exec(ctx, postgres.GINIndex("order"))
		return err
	}),
)
if err := pg.Migrate(ctx); err != nil { ... } // tables + pending migrations
if err := pg.Check(ctx); err != nil { ... }   // fail fast at boot

env := ee.MustNew(ee.WithStore(pg), ee.WithBus(b))
```

If pool and DSN options are absent, the store uses `EE_POSTGRES_PRIMARY_DSN` and `EE_POSTGRES_REPLICA_DSNS`. Separate replica DSNs with commas.

## Primary and replicas

| Operation | Pool |
|-----------|------|
| Actions, `Create`, `Update`, `Delete`, outbox, and migrations | Primary |
| `EntityController.Get`, `EntityController.Find`, and `AggregateController.Get` | Replicas in round-robin order |

Replica reads can lag. For read-your-writes behavior, force the primary for one call:

```go
orders.Get(postgres.ForcePrimary(ctx), id)
```

Without replicas, all operations use the primary.

## Tables

The store uses `ee_states` for JSONB state, `ee_outbox` for the outbox, and `ee_migrations` for applied migration names. See [`sql/schema.sql`](sql/schema.sql).

The ee codec must produce JSON, which is the default.

## Queries and indexes

`Find` generates SQL for each query. Kind and field names become escaped literals. Values remain bound parameters. A server-side cursor streams results. `WithFetchSize` sets the batch size, with default 100. A handler can write while it iterates.

- Equality with `ee.Where(field, v)` uses JSONB containment. `GINIndex(kind)` serves this operation for every field of the kind.
- Ranges and `In` on text or numeric fields use `FieldIndex(kind, field, Text|Numeric)`. The index matches the expression generated by `Find`. `find_internal_test.go` verifies this behavior against the planner. Use the JSON field name.

Use `WithFind(kind, fn)` to replace the generated query for a kind.

## sqlc

The store's SQL files are in `sql/`. `go generate ./...` generates code into `internal/db`.

Your sqlc code can join an ee transaction:

```go
orders.Action(func(ctx *ee.ActionCtx[Order, OrderPaid]) error {
	ptx, _ := postgres.PgxTx(ctx.Tx())
	open, err := mydb.New(ptx).CountOpenOrders(ctx, ctx.Event().Merchant)
	...
})
```

`Store.Primary()` exposes the write pool for sqlc code outside ee.

## Semantics

- Optimistic writes use version-checked `UPDATE` and `DELETE` statements. Inserts use `INSERT ... ON CONFLICT DO NOTHING`. A stale version or duplicate insert returns `store.ErrConflict` without aborting the transaction. `ee.Dedup` relies on this behavior. Serialization failures and deadlocks also map to `ErrConflict`, so ee retries the unit of work.
- Direct `Get` and `Find` can use a replica. `ee.WithPrimary(ctx)` forces the read onto the primary. `postgres.ForcePrimary` provides the same behavior.
- `OutboxStats` reports the unpublished backlog, including leased entries.
- `Claim` serializes claimers with an advisory lock. It skips an entry while an older entry with the same partition key is leased. Every replica can relay entries while per-key publication order is preserved.

## Tests

Set `EE_POSTGRES_TEST_DSN` to enable integration tests. These tests truncate the ee tables.

Set `EE_POSTGRES_TEST_REPLICA_DSN` to enable the replica routing test. Any other database is sufficient. The store also runs the shared `ee/store/storetest` conformance suite.

```sh
docker run -d --rm --name ee-pg -e POSTGRES_PASSWORD=ee -e POSTGRES_USER=ee -p 55432:5432 postgres:17-alpine
docker exec ee-pg psql -U ee -c 'CREATE DATABASE ee_replica'
EE_POSTGRES_TEST_DSN='postgres://ee:ee@localhost:55432/ee?sslmode=disable' \
EE_POSTGRES_TEST_REPLICA_DSN='postgres://ee:ee@localhost:55432/ee_replica?sslmode=disable' \
go test ./...
```
